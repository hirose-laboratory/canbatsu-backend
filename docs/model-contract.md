# AI⇔アプリの受け渡しルール

AIとUnityの間でやり取りするデータの形をここで決める
**データ集めを始める前にクラス定義を確定させよう** (あとから変えるとラベル付けが全部やり直しになってめんどくさい)

## 1. 検出結果 → AR表示 (毎フレーム)

Unity側 (Sentis) が推論結果をこの形に整えてAR表示に渡す

```
TreeDetection {
  screenRect: 画面上の位置 (x, y, w, h)
  worldPosition: 3D位置 (x, y, z)      ← 距離推定ができたら
  kind: 対象木 | 腐朽木 | 曲がり木 | かかり木   ← TODO: クラス定義をチームで決める
  confidence: 信頼度 0〜1
  diameterCm: 推定直径 (cm)
}
```

- 1本ごとの判定結果は**DBに保存しない** (その場のAR表示だけ)
- 伐採本数はUnity側がカウントして、作業終了時の記録 (work_records.felledCount) に入れる

## 2. 計画パラメータ → AI判定 (作業開始時)

アプリが選択中の作業計画 (Firestoreのwork_plans) から渡す
**フィールド名と単位はDB定義に合わせる** (`Firebaseフィールド一覧.md` からコピペしよう)

| パラメータ | 型 | 意味 |
|---|---|---|
| thinningRate | number | 間伐率。0.3 = 30% (30って入れないように) |
| spacingThresholdM | number | 伐採間隔のしきい値 (m)。この間隔**以上**を確保するように選木 |
| diameterThresholdCm | number | 伐採基準。この直径 (cm) **未満**の木を伐る |
| areaPolygon | GeoPoint配列 | 作業範囲の多角形。GeoPoint(緯度, 経度) の順 (逆にすると山が海になる) |

この値は森林簿 (`forestry/` で入れた forest_registry) の樹種・林齢からアプリが簡易式で
自動算出した初期値を、ユーザーが修正したもの。AI側はこの値をそのまま判定に使えばOK
(算出式はアプリ側の ThinningCalculator.cs にある。良くしたい人はそこを見て → 将来はML化したい)

## 3. モデルの入出力 

| 項目 | 決めること | 決定 |
|---|---|---|
| 入力画像サイズ | 例: 640x640 | 未定 |
| 形式 | ONNX (Unity Sentisで読める形) | ONNX |
| クラスID対応表 | 0=対象木, 1=腐朽木, ... みたいな対応 | 未定 |
| 直径推定の方式 | 検出と同時 or 別モデル | 未定 |
| 動作速度の目標 | Beam Pro実機で何fps必要か | 未定 |



 **YOLOv8n (軽量版) をBeam Pro実機で動かして速度を測る(これは学校来た時に試す)**
遅かったら推論間隔を空ける設計に変える必要がある
